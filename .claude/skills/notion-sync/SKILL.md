# notion-sync — ส่งงานขึ้นกระดานกลางที่ Claude chat อ่าน

Klui ใช้ Notion เป็น **กระดานกลางระหว่างฝั่งเขียนโค้ด (Claude Code) กับฝั่งแชท (เลขา AI)**
ฝั่งแชทมี Scheduled Task รันทุกวันและอ่าน "entry ล่าสุดของโปรเจกต์นั้น" เป็นสถานะปัจจุบัน
ถ้าไม่ส่งขึ้นไป **ฝั่งแชทจะเข้าใจว่างานหยุดอยู่ที่วันสุดท้ายที่มีแถว** — เคยค้างมาแล้ว 9 วัน

## ขั้นตอน

### 1. หาที่คั่นหน้า

Notion เองคือที่คั่นหน้า — ไม่ต้องเก็บ state ที่ไหน

```
query_data_sources บน collection://8b131f26-d05a-41f8-bf74-b48339a0a2f9
SELECT "date:วันที่:start" AS d, "หัวข้อ" AS t FROM "collection://8b131f26-..."
WHERE "หัวข้อ" LIKE '💻%' ORDER BY d DESC LIMIT 5
```

แถว 💻 ล่าสุดลงวันไหน = สรุปไปถึงวันนั้นแล้ว ให้ทำต่อจาก **วันถัดไป**

### 2. รวบรวมว่าเกิดอะไรขึ้นตั้งแต่นั้น

```bash
git log --all --since=<วันถัดจากแถวล่าสุด> --date=short --format='%ad|%h|%s' --no-merges \
  --invert-grep --grep='^chore(stamp)'
```

`chore(stamp)` เป็น commit อัตโนมัติของ Stop hook ไม่ใช่งานจริง — **ตัดทิ้งเสมอ**

แหล่งอื่นที่ควรดูประกอบ (ตามลำดับความน่าเชื่อถือ):
1. **บทสนทนาในเซสชันนี้** ← ดีที่สุด เป็นที่เดียวที่รู้ว่า "ตัดสินใจอะไร เพราะอะไร"
2. `HANDOFF*.md` ที่ออกใหม่ในช่วงนั้น (`ls -t HANDOFF*.md | head -3`)
3. commit message (โปรเจกต์นี้เขียนละเอียดเป็นภาษาไทย ใช้ได้จริง)
4. transcript ในเครื่อง `~/.claude/projects/<โปรเจกต์>/*.jsonl` — ใช้เมื่อต้องกู้ย้อนหลังข้ามเซสชัน
   ⚠️ เซสชันที่ถูก compact จะเขียนไฟล์ใหม่ที่ replay ประวัติเดิม → **วันติดกันมีข้อความซ้ำ อย่านับซ้ำ**

### 3. เขียนแถวใหม่ — 1 แถว = 1 วัน × 1 โปรเจกต์

**หัวข้อขึ้นต้นด้วย `💻` เสมอ** (เครื่องหมายว่ามาจาก Claude Code ไม่ใช่ฝั่งแชท — Klui ใช้กรอง/ลบทั้งชุดได้)
วันติดกันที่เป็นงานเรื่องเดียวกันต่อเนื่อง รวมเป็นแถวเดียวแล้วใส่ `date:วันที่:end` ได้

| ช่อง | เขียนอะไร |
|---|---|
| `หัวข้อ` | `💻 <วันที่ย่อ> — <สิ่งที่ทำ 2-3 อย่างหลัก>` |
| `คุยเรื่อง` | จำนวนเซสชัน/ข้อความ/commit + ทำอะไรบ้างแบบ 1 ย่อหน้า |
| `ตัดสินใจ` | ①②③ ของที่ **ตัดสินไปแล้ว** พร้อมเหตุผลสั้นๆ |
| `Action items` | งานค้าง นำหน้าแต่ละข้อด้วย 🔴 |

**`ตัดสินใจ` คือช่องที่มีค่าที่สุด** — มันกันไม่ให้เซสชันหน้ามารื้อของที่ตกลงกันไปแล้ว
(เช่น *"ฟอนต์กลับ Kanit ล้วน ห้ามเสนอเปลี่ยนซ้ำ"* · *"ทาง A ให้ผู้ใช้เลือกบัญชี Google เองตกแล้ว"*)
ถ้าไม่มีบทสนทนาให้ดู **อย่าเดาเหตุผล** — เขียนเท่าที่ commit บอกจริง แล้วบอก Klui ว่าช่องนี้ตื้นเพราะสรุปย้อนหลัง

**เนื้อในหน้า** เปิดด้วยหัวข้อ `## 🔴 ค้างเมื่อจบวัน` เสมอ (Klui สั่งให้เน้นงานค้างมากกว่าเล่าว่าทำอะไร)
แล้วค่อยตามด้วย: ทำอะไรไปบ้าง · ตารางตัดสินใจ+เหตุผล · ⚠️ บทเรียนจากของที่พัง · เอกสารที่ออกวันนั้น

### 4. อัปเดต Pending Items

- **เทียบชื่อกับของเดิมก่อนสร้างใหม่ทุกครั้ง** — ฝั่งแชทก็เขียน DB นี้ อย่าสร้างซ้ำ
- งานที่เสร็จแล้ว → ติ๊ก `เสร็จแล้ว = __YES__` **แต่ถ้าเป็นแถวที่ฝั่งแชทสร้างไว้ ให้ถาม Klui ก่อน** (บางแถวรวมหลายเรื่องที่สถานะไม่เหมือนกัน)
- งานค้างใหม่ → เพิ่มแถว พร้อม `หมายเหตุ` ที่บอก **กับดัก/ข้อควรระวัง** ไม่ใช่แค่ชื่องาน

### 5. ปิดงาน

เขียน commit ปัจจุบันลงไฟล์ marker เพื่อให้ตัวเตือนรู้ว่าซิงค์ถึงไหนแล้ว:

```bash
git rev-parse HEAD > .claude/.last-notion-sync
```

แล้วรายงาน Klui เป็นภาษาไทย: เพิ่มกี่แถว · ช่วงวันที่ไหน · งานค้างที่เพิ่ม/ปิด · ลิงก์แถวใหม่

## กฎที่ห้ามลืม

- **ภาษาไทยทั้งหมด** — Klui อ่านภาษาไทย
- **append only** — ห้ามแก้/ลบแถวที่ฝั่งแชทเขียน
- **ห้ามสร้าง DB ใหม่** (ดูเหตุผลด้านบน)
- **โทนงานค้างต้องตรงไปตรงมา แต่ changelog ที่ผู้ใช้แอปเห็นต้องไม่ชวนตกใจ** — คนละเรื่องกัน อย่าปนกัน
- ไม่ต้องยกชื่อเพื่อนร่วมงานเข้า Notion ถ้าไม่จำเป็นต่อการเข้าใจงาน
- ถ้าไม่มีอะไรใหม่ตั้งแต่แถวล่าสุด → **บอกว่าไม่มีอะไรต้องส่ง แล้วจบ** อย่าสร้างแถวเปล่า
